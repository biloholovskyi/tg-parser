# Ручное тестирование — дайджест и хранение сессий

Артефакт к блоку 10. Покрывает маршруты `PUT /digest/session` и `POST /digest/run`, хранение сессий в Redis и доставку дайджеста в Telegram-бота.

Парный файл для Postman: [digest-postman-collection.json](digest-postman-collection.json).

## Предусловия

- Сервис собран и запущен: `rtk npm run build`, затем `rtk npm run start:prod`.
- Переменные из [telegram-manual-testing.md](telegram-manual-testing.md): `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `API_KEYS`.
- Хранение сессий: `REDIS_URL`, `SESSION_ENCRYPTION_KEY` — настройка в [docs/deployment/railway-redis.md](../deployment/railway-redis.md). Локально: `docker run -d -p 6379:6379 redis:7-alpine`.
- Дайджест: `DIGEST_CHANNELS` (2–3 публичных канала с постами за сутки), `GROK_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_CHAT_ID`. `GROK_MODEL`, `DIGEST_CRON`, `DIGEST_TIMEZONE` — по умолчанию.
- Бот добавлен в чат `TELEGRAM_BOT_CHAT_ID` и может в него писать (для личного чата — вы написали боту `/start`).
- Базовый адрес в примерах: `http://127.0.0.1:8080`.

## Модель авторизации

- Каждый маршрут требует `x-api-key` из `API_KEYS`.
- `sessionString` получается через `POST /telegram/auth` (см. [telegram-manual-testing.md](telegram-manual-testing.md)) и передаётся только заголовком `x-session-string`. Хранить в переменной Postman, не коммитить.
- `PUT /digest/session` отмечает сессию, от имени которой дайджест читает каналы. Строка сессии в Redis не хранится в открытом виде: ключ — хеш, значение зашифровано.

## Осторожно

- `POST /digest/run` тратит токены Grok и пишет в реальный чат. Запускайте с 2–3 каналами.
- Второй запуск во время первого отвечает 409 — это ожидаемо.

## Случаи

### Строки лога при старте

| № | Условие | Ожидаемый результат |
|---|---------|---------------------|
| L1 | Заданы `REDIS_URL` и верный ключ | `[RedisModule] Session persistence: Redis`, затем `[Redis] Connected` |
| L2 | `REDIS_URL` не задан | одно предупреждение `REDIS_URL is not set: sessions are kept in memory only` |
| L3 | Ключ не 32 байта | одно предупреждение про `SESSION_ENCRYPTION_KEY`, режим «только память» |
| L4 | Все переменные дайджеста заданы | `Digest scheduled: "0 23 * * *" Europe/Kyiv` |
| L5 | Не хватает переменных дайджеста | `Digest disabled, not set: ...` с именами, без значений |

### Хранение сессий

| № | Шаги | Ожидаемый результат |
|---|------|---------------------|
| S1 | Авторизоваться, `GET /telegram/me` с сессией | 200 `{"status":"success"}` |
| S2 | Перезапустить сервис, повторить S1 с той же строкой | 200 `{"status":"success"}` без повторной авторизации |
| S3 | В Redis посмотреть ключи `tg:session:*` | 64 шестнадцатеричных символа после префикса; значение — base64, строки сессии нет |
| S4 | Остановить Redis, перезапустить сервис, `GET /telegram/me` | 503 `Session storage is unreachable, retry later` |
| S5 | Redis работает, `GET /telegram/me` со строкой, которую сервис не выдавал | 200 `{"status":"failed"}` |
| S6 | Сменить `SESSION_ENCRYPTION_KEY`, перезапустить, `GET /telegram/me` со старой сессией | 200 `{"status":"failed"}`, запись удалена из Redis |

### `PUT /digest/session`

| № | Запрос | Ожидаемый результат |
|---|--------|---------------------|
| D1 | Без `x-api-key` | 401 |
| D2 | С ключом, без `x-session-string` | 400 `A session string is required in the x-session-string header` |
| D3 | С ключом и неизвестной сессией | 401 `Session is invalid or revoked, authenticate again` |
| D4 | С ключом и рабочей сессией | 204, пустое тело; в логе `Digest session marked`; в Redis ключ `tg:digest-session` с хешем |
| D5 | Сессия в query `?sessionString=...` вместо заголовка | 400, как D2 |

### `POST /digest/run`

| № | Запрос | Ожидаемый результат |
|---|--------|---------------------|
| R1 | Без `x-api-key` | 401 |
| R2 | С ключом, дайджест не настроен | 503 `Digest is not configured` |
| R3 | С ключом, всё настроено, сессия отмечена | 202 `{"status":"started"}`; через 1–3 минуты сообщение в боте |
| R4 | Повторить R3, пока первый запуск идёт | 409 `A digest run is already in progress` |
| R5 | С ключом, сессия не отмечена | 202; в боте «Дайджест не собран» с просьбой вызвать `PUT /digest/session` |
| R6 | В `DIGEST_CHANNELS` добавить несуществующий канал | дайджест приходит, в подвале «Недоступны каналы: @...» |
| R7 | Более 60 запросов в минуту одним ключом | 429 с `Retry-After` |

### Содержание дайджеста

| № | Проверка | Ожидаемый результат |
|---|----------|---------------------|
| C1 | Подвал | «Учтено N из N постов», N совпадает с числом постов в заголовке |
| C2 | Ссылки под тезисами | каждая ведёт на пост, подпись `@channel/id` |
| C3 | Посты об одном событии из разных каналов | один тезис с несколькими ссылками |
| C4 | Противоречащие версии | тезис нейтральный, версии подпунктами с каналом-источником |
| C5 | Тон | без оценок и выводов; выборочно сверить три тезиса с постами |
| C6 | Длинный дайджест | несколько сообщений, каждое открывается без ошибки разметки |
| C7 | Пост только с медиа | ссылка в блоке «Посты без текста» |

### Расписание

| № | Шаги | Ожидаемый результат |
|---|------|---------------------|
| T1 | `DIGEST_CRON` на ближайшую минуту, перезапуск | в назначенное время дайджест в боте, в логе строка `Digest scheduled: ...` |
| T2 | Во время запланированного запуска вызвать `POST /digest/run` | 409 |
