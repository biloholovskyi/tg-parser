# Phase 02 — Контроллер и DTO

Статус: done

Требуемые правила: `.claude/rules/testing.md`, `.claude/rules/api-contracts.md`, `.claude/rules/patterns.md`

## Цель

Каждый маршрут и каждая форма запроса закрыты проверками, включая отклонение неверного ввода.

## Заметки по реализации

Спек контроллера использует подменённый `TelegramService`. Проверки DTO исполняют настоящий `class-validator`, а не подменяют его.

## Объём

- По одной проверке на каждый маршрут: health, авторизация, проверка сессии, выборка постов.
- Отсутствующие обязательные параметры дают ожидаемый отказ.
- DTO: happy path и как минимум один случай отклонения на каждую форму запроса.
- Диапазонные ограничения параметра периода проверены на границах.
- Контроллер делегирует работу сервису и не содержит логики сверх разбора запроса.

## Команды проверки

- `rtk npm test`
- `rtk npm run test:cov`

## Критерии приёмки

- Покрытие `telegram.controller.ts` и каталога `dto/` по строкам не ниже 0.8.
- Каждый маршрут имеет минимум одну проверку.

## Доказательства

- Создан `src/telegram/telegram.controller.spec.ts`: 24 проверки, `TelegramService` подменён, GramJS не загружается.
- Каждый маршрут проверен: health, auth, me, posts; метки `PublicRoute` и `PhoneRateLimited` стоят только на своих маршрутах.
