# Phase 03 — E2E

Статус: todo

Требуемые правила: `.claude/rules/testing.md`, `.claude/rules/architecture.md`

## Цель

Приложение поднимается целиком и отвечает по HTTP предсказуемо, ни разу не обращаясь к Telegram.

## Заметки по реализации

Сценарии пишутся с нуля в `test/`. Приложение поднимается через тестовый модуль Nest с подменённым провайдером `TelegramService`.

## Объём

- Health-маршрут отвечает при отсутствующих переменных окружения Telegram.
- Полный цикл авторизации по шагам с подменённым сервисом.
- Выборка постов: успешный ответ и отказ при отсутствии сессии.
- Отклонение неверного тела запроса на уровне приложения.
- Ни один сценарий не создаёт настоящий клиент и не открывает соединение.

## Чеклист

- [ ] Сценарии в `test/*.e2e-spec.ts`
- [ ] `TelegramService` подменён провайдером
- [ ] Проверено отсутствие сетевых обращений
- [ ] Прогон стабилен при повторном запуске

## Команды проверки

- `rtk npm run test:e2e`

## Критерии приёмки

- Прогон E2E зелёный и занимает меньше минуты.
- Отсутствие переменных окружения Telegram не мешает старту приложения в тесте.
