# Phase 01 — Юнит-тесты сервиса

Статус: done

Требуемые правила: `.claude/rules/testing.md`, `.claude/rules/telegram.md`, `.claude/rules/patterns.md`

## Цель

Каждый публичный метод сервиса и каждая ветка отображения ошибки закрыты проверкой с подменённым GramJS.

## Заметки по реализации

Спек-файл сервиса пишется с нуля. Клиент GramJS подменяется на границе сервиса, таймеры — поддельные. Автор — агент `test-writer`.

## Объём

- Авторизация: запрос кода, проверка кода, ветка с паролем 2FA, повторный запрос кода по тому же номеру.
- Очистка состояния авторизации по истечении срока, с поддельными таймерами.
- Кэш клиентов: попадание, промах, поведение при пустом кэше после перезапуска.
- Жизненный цикл: отключение на успешном пути и на каждой ветке ошибки.
- Выборка постов: пустой канал, выборка внутри окна, выход за окно, остановка обхода.
- Разбор сообщения: текст, отметки вложений, ссылка на пост.
- Проверка сессии: успешная и неуспешная.
- Каждая строка таблицы соответствия ошибок из `.claude/rules/telegram.md`.
- Поведение при отсутствующих учётных данных.

## Чеклист

- [x] Спек сервиса создан, один `describe` на класс, схема AAA в каждой проверке
- [x] GramJS подменён, настоящее соединение не открывается
- [x] В фикстурах только очевидные подделки
- [x] Поддельные таймеры вместо ожидания
- [x] Ни одного `.only` и `.skip`
- [x] Найденные расхождения оформлены находками, продакшен-код не правится

## Команды проверки

- `rtk npm test`
- `rtk npm run test:cov`

## Критерии приёмки

- Покрытие `telegram.service.ts` по строкам не ниже 0.8.
- Каждая ветка отображения ошибки имеет отдельную проверку.
- Прогон не делает сетевых обращений.

## Доказательства

- Спек сервиса существовал до старта (план писался до блоков 01-05); фаза закрыла остаток: 22 новые проверки в `src/telegram/telegram.service.spec.ts`.
- `rtk npm run test:cov`: `telegram.service.ts` 100% по строкам, веткам и функциям; всего 462 из 462 тестов, 23 набора.
- Закрыто: очистка просроченных попыток входа на поддельных таймерах, отсутствие учётных данных, восстановление клиента после перезапуска, отметки вложений, сбои файлового хранилища, 503 и 502 на ветках авторизации.
- Продакшен-код не менялся, `.only` и `.skip` нет, сеть не используется.

## Находки (передаются в профильные блоки, здесь не чинятся)

- Без `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` ответ 500 даёт только `authenticate`; `getClient` при восстановлении сессии из файла создаёт клиент с `apiId 0` и пытается подключиться.
- Ветка `catch` в конструкторе недостижима: `getTelegramConfig` не бросает ошибок.
- Если удаление записи из `auth-states.json` после входа не удалось, на диске остаются телефон и хэш кода, а следующий шаг 2 откроет лишнее подключение.
- Known Deviation: файловое хранилище делает синхронный ввод-вывод на пути запроса.
