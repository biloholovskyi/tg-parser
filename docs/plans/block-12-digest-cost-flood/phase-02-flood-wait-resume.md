# Phase 02 — Ожидание лимита и продолжение сбора (Часть Б)

## Статус

done

## Правила

`.claude/rules/runtime-resources.md`, `.claude/rules/testing.md`

## Цель

Короткое ограничение Telegram во время сбора выдерживается, и сбор продолжается с того же канала вместо срыва дайджеста.

## Подсказки по реализации

- Пауза — отдельный помощник в `src/digest/utils/` с `AbortSignal`: таймер очищается и при срабатывании, и при отмене, у таймера `unref()`.
- `PostCollector` получает сигнал отмены от `DigestService`; `DigestService.onModuleDestroy` отменяет текущий запуск.
- Отменённый запуск ничего не отправляет в бот и пишет одну строку лога.

## Объём

- `src/digest/constants.ts`: `DIGEST_FLOOD_WAIT_MAX_S` (1800), `DIGEST_FLOOD_WAIT_TOTAL_MAX_S` (3600), `DIGEST_FLOOD_WAIT_MARGIN_S` (5).
- `src/digest/post-collector.ts`: на `TooManyRequestsException` в пределах лимитов — warn, `alerts.warning('Digest waiting for Telegram flood limit', { channel, seconds })`, пауза, повтор того же канала; сверх лимитов — ошибка уходит в `DigestService` и прерывает запуск.
- `src/digest/digest.service.ts`: отмена запуска при остановке модуля.
- Тесты на поддельных таймерах: ожидание и продолжение, превышение одного ожидания, превышение суммы, отмена во время паузы без отправки, 409 на ручной запуск во время ожидания.

## Критерии приёмки

- При 429 с ожиданием в пределах `DIGEST_FLOOD_WAIT_MAX_S` дайджест собирается полностью и приходит с задержкой.
- При ожидании сверх предела в бот приходит сообщение «Telegram ограничил частоту запросов», а в логе видна длительность.
- Остановка процесса во время паузы не ждёт её окончания.

## Evidence

- lint, build зелёные; `rtk npm test`: 65 suites, 1410 tests, 0 failures.
- Новые тесты: `src/digest/utils/cancellable-delay.spec.ts`; дополнены `post-collector.spec.ts`, `digest.service.spec.ts`.
- Ожидание в пределах лимитов продолжает сбор с того же канала; сверх лимитов — 429 и сообщение об ошибке.
- Остановка во время паузы завершает запуск сразу, без отправки и без оставшихся таймеров.
