# Reflect — блок 12

## Что сработало

- Порядок фаз: сначала высокорисковая часть Б (кэш каналов, ожидание лимита), потом стоимость. Каждая фаза закрылась с зелёными тестами с первого прогона после `test-writer`.
- Число секунд flood wait нашлось в исходниках GramJS (`FloodWaitError.seconds`), а не в документации: без этого лог 12.10.2026 так и оставался бы `429 (FLOOD)`.
- Учёт токенов через `GrokUsageMeter` в запросе не поменял возвращаемый тип `completeJson`: десятки существующих вызовов и тестов не пришлось переписывать.

## Расхождения с дизайном

- Резервные тезисы переводятся тем же промптом и механизмом, что и посты; отдельного `FALLBACK_TRANSLATION_SYSTEM_PROMPT` нет. `design.md` исправлен.
- Кэш каналов использует Redis при любом `REDIS_URL`, без зависимости от `SESSION_ENCRYPTION_KEY`: значения не шифруются по ADR.
- `CHANNEL_PRIVATE` на запомненном канале тоже даёт один повторный поиск по имени: лишний поиск в редком случае ради простой классификации.

## Уроки

- Мок `telegram/tl` в `telegram.service.spec.ts` перечисляет классы `Api` вручную; любой новый `instanceof Api.X` в продакшен-коде ломает десятки тестов, пока класс не добавлен в мок.
- `delayUnlessCancelled` сначала бросал исключение синхронно при уже отменённом сигнале; функция, возвращающая promise, должна отклонять promise, а не бросать.

## Технический долг

- Поддержка `response_format: json_schema` у `grok-4.20-0309-non-reasoning` не подтверждена документацией xAI; проверяется на первом настоящем запуске.
- Нет теста Nest DI на `TelegramModule` с `ChannelPeerCache` и настоящим `REDIS_CLIENT`; локальный смоук подтвердил только режим памяти.
- Отменяется только сбор постов; запросы Grok и Bot API при остановке дорабатывают до своих таймаутов.
- Частичный дайджест при ожидании сверх лимитов не делался по решению пользователя: такой запуск по-прежнему заканчивается сообщением об ошибке.
