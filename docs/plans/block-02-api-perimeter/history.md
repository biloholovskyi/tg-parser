## Handoff → Phase 03

- Цепочка гвардов в `TelegramModule`: `ApiKeyGuard` → `RateLimitGuard` → `PhoneRateLimitGuard`; порядок важен, счётчики не тратятся на неаутентифицированных.
- `PhoneRateLimitGuard` читает `request.body.phoneNumber` до валидации, поэтому переписанный в Phase 03 DTO авторизации обязан сохранить это имя поля.
- Запрос без пригодного `phoneNumber` ограничитель пропускает дальше — отклонить его должен DTO Phase 03.
- Общий лимит считается по значению заголовка `x-api-key`; при переводе строки сессии в заголовок Phase 03 субъект счёта не меняется.
- Ответ 429 несёт `Retry-After` и `retryAfterSeconds` в теле — это часть контракта, его нужно отразить в артефактах `docs/testing/` в Phase 03.
- `readApiKeyHeader` вынесен в `src/shared/utils/api-key-header.ts`; заголовок сессии Phase 03 стоит читать таким же отдельным хелпером.
- Остаточное: `dropExpiredWindows` проходит всю карту счётчиков на каждый запрос (потолок 1000 записей) — ограниченная, но заметная работа на горячем пути.
