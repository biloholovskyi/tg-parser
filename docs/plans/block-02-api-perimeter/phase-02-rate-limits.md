# Phase 02 — Рейт-лимиты

Статус: done

Требуемые правила: `.claude/rules/api-security.md`, `.claude/rules/runtime-resources.md`, `.claude/rules/testing.md`

## Цель

Объём работы, который вызывающая сторона может заказать у Telegram, ограничен и предсказуем.

## Заметки по реализации

Ограничитель для `auth` считает обращения по номеру телефона, а не по ключу и не по адресу. Счётчики живут в памяти процесса с ограниченным размером и вытеснением по времени — это тот же класс ресурса, что и кэш клиентов.

## Объём

- Общий лимит RATE_LIMIT_DEFAULT применяется ко всем маршрутам, кроме health.
- Отдельный лимит RATE_LIMIT_AUTH применяется к `POST /telegram/auth` и считается по номеру телефона.
- Превышение отдаёт 429 с указанием времени, через которое запрос допустим.
- Хранилище счётчиков ограничено по размеру и очищается по истечении окна.
- Значения лимитов вынесены именованными константами.

## Критерии приёмки

- Повторные обращения к авторизации с одним номером сверх лимита получают 429, другой номер при этом обслуживается.
- Счётчики не растут неограниченно при потоке уникальных номеров.
- Ни одна запись лога ограничителя не содержит номер телефона.

## Результат

- `src/shared/constants/rate-limit.constants.ts` — значения лимитов, длины окон и потолок хранилища именованными константами.
- `src/shared/utils/rate-limit-store.ts` — счётчики с фиксированным окном: субъект хранится только дайджестом, истёкшие окна удаляются при каждом обращении, при достижении потолка вытесняется самое старое окно.
- `src/shared/guards/rate-limit.guard.ts` — общий лимит по значению `x-api-key` на всех маршрутах, кроме помеченных публичными.
- `src/shared/guards/phone-rate-limit.guard.ts` — лимит по номеру телефона только на маршруте с меткой `@PhoneRateLimited()`; два разных ключа с одним номером делят счётчик.
- `src/shared/exceptions/too-many-requests.exception.ts` и `src/shared/utils/rate-limit-response.ts` — 429 с заголовком `Retry-After` и полем `retryAfterSeconds`.
- Ни один ограничитель ничего не пишет в лог; тесты проверяют это шпионами на все уровни логгера.
- Проверки: `rtk npm run lint` — чисто, `rtk npm run build` — успешно, `rtk npm test` — 16 наборов, 168 тестов, все зелёные.
