# Блоки 08-09 — Целевая структура модуля

## Разделение ответственностей

| Единица | Ответственность |
|---------|-----------------|
| `TelegramController` | Разбор запроса, делегирование, форма ответа |
| `AuthService` | Многошаговая авторизация: запрос кода, проверка кода, пароль 2FA, состояния попыток |
| `SessionStore` | Владение кэшем клиентов: выдача, потолок, срок жизни, вытеснение с отключением, остановка |
| `ChannelService` | Обход сообщений канала, применение временного окна, потолок выборки |
| `message.mapper` | Преобразование сообщения MTProto в форму ответа, без состояния |
| `constants.ts` | Числовые пределы модуля с единицами измерения в именах |
| `telegram-client.factory` | Единственное место создания клиента GramJS с явными опциями |

## Правила границ

- Клиент GramJS создаётся только фабрикой; `AuthService` и `ChannelService` получают его через `SessionStore`.
- `SessionStore` — единственный владелец жизненного цикла клиента: никто другой не подключает и не отключает.
- `message.mapper` не имеет состояния и не обращается к сети.
- Контроллер не знает о GramJS.
- Обмен между единицами идёт через типы из `interfaces/`, а не через формы MTProto.

## Ограничения структуры

- Класс не длиннее 200 строк, функция не длиннее 20 при пороге рефакторинга 30, вложенность не глубже 3.
- Пять параметров и более передаются объектом.
- Числовой литерал больше единицы выносится в константу с единицей измерения в имени.

## Режим компилятора

Целевое состояние: `strictNullChecks` и `noImplicitAny` включены. Результаты MTProto сужаются на границе сервиса, а не приводятся к свободному типу. Отсутствующее значение обрабатывается явно там, где оно возможно.
