# Phase 01 — Решение по хранилищу сессий

Статус: todo

Требуемые правила: `.claude/rules/telegram.md`, `.claude/rules/drift-audit.md`, `.claude/rules/runtime-resources.md`, `.claude/rules/implementation-plans.md`

## Цель

Открытая развилка по хранению сессий закрыта решением пользователя, зафиксированным в ADR, и код приведён в соответствие с ним.

## Заметки по реализации

Фаза начинается с документа, а не с кода. Варианты и их цена собраны в `research.md`. Решение принимает пользователь; исполнитель его оформляет и применяет.

## Объём

- ADR `adr-session-storage.md` в папке плана: контекст, варианты, решение, последствия, дата.
- Раздел Known Deviations в `.claude/rules/telegram.md` закрыт: описание развилки заменено описанием принятого положения дел.
- Утверждение о модели сессий в `CLAUDE.md` приведено в соответствие с решением.
- Если выбран отказ от файлов: файловые методы и связанный синхронный ввод-вывод удалены, каталог `data/` не создаётся при запуске.
- Если выбрано внешнее хранилище: источник и порядок шифрования описаны в ADR, а реализация вынесена отдельным планом и здесь не выполняется.
- Правило `.claude/rules/api-security.md` о запрете хранения учётных данных в файлах соблюдено по факту.

## Чеклист

## Команды проверки

- `rtk npm run lint`
- `rtk npm run build`
- `rtk npm test`

## Критерии приёмки

- Ни один файл под `data/` не создаётся и не читается при обычной работе, если выбран отказ от файлов.
- В правилах не остаётся формулировки об открытой развилке.
- Тесты подтверждают корректное поведение при строке сессии, для которой нет клиента в памяти.
