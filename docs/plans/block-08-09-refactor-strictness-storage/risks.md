# Блоки 08-09 — Риски

## Режимы отказа

| Режим | Последствие | Признак |
|-------|-------------|---------|
| Перемещение кода меняет поведение незаметно | Регрессия в авторизации без явной ошибки | Тесты зелёные, но живой сценарий ломается |
| Отказ от файлов без предупреждения потребителей | После выката все сессии требуют повторной передачи строки | Всплеск отказов на маршрутах, требующих сессию |
| Внешнее хранилище выбрано, но ключ шифрования утрачен | Сессии нечитаемы, требуется полная переавторизация | Ошибки расшифровки при старте |
| Строгость включена без разбора последствий | Сборка не проходит, работа встаёт | Большое число ошибок компиляции разом |
| Распил без покрытия тестами | Ошибка обнаруживается только в проде | Низкое покрытие на момент старта фазы |

## Радиус поражения

Весь модуль Telegram. Это единственный блок, который трогает все методы сразу, поэтому он несовместим по времени с блоком 03-05.

## Цена недели с ошибкой в проде

- Оставленное файловое хранилище: учётные данные лежат на диске, и любой доступ к контейнеру или к образу равен доступу ко всем аккаунтам. Стоимость измеряется не деньгами, а компрометацией.
- Регрессия после распила: отказ авторизации на всём потоке пользователей, откат на предыдущий релиз.
- Незавершённая строгость: смешанный режим, когда часть кода проверяется, а часть нет, и это принимают за проверенный код.

## Экспозиция секретов

Максимальная из всех блоков: работа идёт ровно с тем местом, где сегодня хранятся строки сессий и номера телефонов. Требования на время работ: не открывать содержимое файлов состояния, не переносить значения в тесты и артефакты, удалять файлы состояния только после того, как решение зафиксировано в ADR.

## Ход отката

- Phase 01 не меняет код и откату не подлежит: ADR остаётся документом решения.
- Phase 02 откатывается выкатом предыдущего релиза; внешнее состояние не затрагивается.
- Phase 03 откатывается возвратом настроек компилятора; изменения типов при этом остаются безвредными.
- Отказ от файлового хранилища необратим для уже выданных сессий: перед выкатом потребители предупреждаются, что строку сессии нужно передавать заново после перезапуска.
