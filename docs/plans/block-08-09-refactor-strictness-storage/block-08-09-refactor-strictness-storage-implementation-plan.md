# Блоки 08-09 — Хранилище, распил сервиса, строгость TypeScript

Объединяет три работы, которые по-разному, но одинаково широко задевают весь модуль Telegram и потому не могут идти параллельно ни с ним, ни друг с другом.

## Миссия

- Судьба файлового хранилища сессий решена явно и зафиксирована в ADR.
- Сервис разделён по ответственностям: авторизация, хранение сессий, работа с каналами, преобразование сообщений.
- Компилятор проверяет обязательность типов и обработку отсутствующих значений во всём проекте.

## Профиль задачи

`hybrid` — 2 сигнала feature (архитектурная развилка по хранилищу, новая структура модуля) и 2 сигнала bugfix (устранение хранения учётных данных на диске, вскрытие необработанных отсутствующих значений).

## Тир сложности

`standard` — затронуты хранение секретов, кэш сессий и жизненный цикл клиента.

## Целевая версия

1.4.1 (указана пользователем).

## Порядок и границы

- Фазы строго последовательны: решение о хранилище определяет, что хранит выделенный компонент; строгость включается последней, когда файлы перестали двигаться.
- Блок запускается после блока 03-05. Запускать его параллельно с ним нельзя: обе работы правят одни и те же методы.
- Блоки 01, 02, 06 и 07 этому плану не мешают и могут идти одновременно.
