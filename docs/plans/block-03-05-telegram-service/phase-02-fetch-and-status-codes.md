# Phase 02 — Выборка постов и коды ответов

Статус: todo

Требуемые правила: `.claude/rules/telegram.md`, `.claude/rules/patterns.md`, `.claude/rules/api-contracts.md`, `.claude/rules/testing.md`

## Цель

Выборка за период полна в пределах объявленного потолка, а любой отказ Telegram отражён верным кодом состояния.

## Заметки по реализации

Расчёт лимита заменяется постраничным обходом: страницы запрашиваются последовательно, пока сообщения попадают во временное окно и не превышен общий потолок. Признак обрезки добавляется в форму ответа в `interfaces/`.

## Объём

- Обход идёт постранично с размером страницы и общим потолком из именованных констант.
- Обход прекращается при выходе за временное окно или при достижении потолка.
- Ответ содержит признак того, что выборка обрезана потолком, и потребитель может это отличить от полной выборки.
- Соответствие ошибок и кодов: недействительная или отозванная сессия — 401; канал не найден или недоступен — 404; истёкший или неверный код, неверный пароль — 400 с различимым сообщением; ограничение частоты — 429 с длительностью ожидания; отсутствующие учётные данные — 500 с сообщением о конфигурации.
- Исходная ошибка сохраняется как причина при оборачивании; наружу не уходит ни текст MTProto, ни стек.
- Проверка сессии различает недействительную сессию и сбой связи.

## Критерии приёмки

- Запрос за большое окно возвращает либо полную выборку, либо выборку с признаком обрезки, но никогда неполную без признака.
- Тест на каждую строку таблицы соответствия ошибок зелёный.
- Ответ при ограничении частоты содержит длительность ожидания и не удерживает запрос дольше порога из констант.
