# Phase 03 — Логирование

Статус: done

Требуемые правила: `.claude/rules/patterns.md`, `.claude/rules/telegram.md`, `.claude/rules/runtime-resources.md`, `.claude/rules/testing.md`

## Цель

Логи сервиса состоят из исходов операций и не содержат персональных данных и учётных данных.

## Заметки по реализации

Замена построчная, по методам. Методы, затронутые фазами 01 и 02, переводятся на журнал в ходе тех фаз; эта фаза добивает остальное и закрепляет правило.

## Объём

- Весь вывод идёт через `Logger` с контекстом модуля.
- В логах нет номеров телефонов, строк сессии, их префиксов и длин, ключей кэша, кодов подтверждения и паролей.
- Отладочные артефакты убраны: счётчик экземпляров сервиса, отметки прогресса по каждым десяти сообщениям, вывод ключей кэша.
- На один запрос приходится одна запись об исходе; прогресс и внутренние счётчики уходят на уровень отладки, выключенный по умолчанию.
- Ошибки логируются с контекстом операции, без полезной нагрузки запроса и без содержимого приватных каналов.

## Команды проверки

- `rtk npm run lint`
- `rtk npm run build`
- `rtk npm test`

## Критерии приёмки

- Поиск по `src/` не находит `console.`.
- Ручной просмотр журнала одного полного цикла авторизации не содержит номера телефона и строки сессии.
- Объём логов на один запрос выборки не зависит от числа обработанных сообщений.

## Итог

- Весь вывод `src/` идёт через `Logger`; `console.*` запрещён правилом `no-console` в `.eslintrc.js` для `src/**/*.ts` и тестом `src/no-console.spec.ts`.
- Один запрос даёт одну запись об исходе; отказы пишутся через `failWith`: 4xx — warn, 5xx — error, с кодом MTProto из `describeError`.
- Счётчик экземпляров сервиса и построчный прогресс удалены; восстановление из файла — на уровне debug, выключенном в `src/main.ts`.
- Тесты проверяют, что в логах полного цикла авторизации нет номера, кода, пароля и строки сессии, и что число строк выборки не зависит от числа сообщений.
- lint, build, `rtk npm test` (378) проходят.
