# Блоки 03-05 — Риски

## Режимы отказа

| Режим | Последствие | Признак |
|-------|-------------|---------|
| Слишком короткий TTL простоя | Частое переподключение, рост обращений к Telegram | Повторные подключения по одной сессии в логах |
| Вытеснение без отключения | Утечка сохраняется, но становится невидимой | Память растёт при стабильном размере кэша |
| Низкий порог ожидания при флуд-вейте | Клиент получает 429 на ожиданиях, которые допустимо переждать | Рост доли 429 без роста нагрузки |
| Постраничный обход без потолка | Один запрос занимает процесс надолго | Длительные запросы на большом окне |
| Новый код состояния ломает разбор у потребителя | Интеграция считает 401 или 429 аварией | Ошибки на стороне потребителя при штатной работе сервиса |

## Радиус поражения

Единственный рабочий путь сервиса. Ошибка в вытеснении затрагивает все активные сессии сразу; ошибка в выборке — все обращения к каналам.

## Цена недели с ошибкой в проде

- Утечка сохраняется: число живых соединений растёт с каждой обслуженной сессией, каждое шлёт ping раз в девять секунд бесконечно. Память и процессорное время растут до перезапуска, после перезапуска все клиенты переавторизуются.
- Молчаливое усечение сохраняется: потребитель неделю принимает неполные выборки за полные и строит на них решения. Это дороже утечки, потому что обнаруживается поздно.
- Слишком агрессивное вытеснение: постоянная переавторизация, риск ограничений со стороны Telegram на аккаунт.

## Экспозиция секретов

Прямая. Фаза логирования убирает из вывода номера телефонов, префиксы и длины строк сессии. До её завершения любой снимок логов содержит персональные данные. Тесты используют только очевидные подделки.

## Ход отката

Пофазный. Каждая фаза самодостаточна и откатывается отдельным выкатом. Значения потолка, TTL и порога ожидания вынесены константами, поэтому смягчение поведения не требует правки логики. Состояния в Telegram фазы не меняют: откат кода полностью возвращает прежнее поведение.
