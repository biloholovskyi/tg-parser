# Блоки 03-05 — Research

## Затрагиваемые файлы

- `src/telegram/telegram.service.ts` — 544 строки: авторизация, кэш клиентов, выборка сообщений, файловое хранилище
- `src/telegram/interfaces/message.interface.ts` — формы ответа

## Наблюдаемое состояние

- Клиенты хранятся в `Map<sessionString, TelegramClient>` без потолка и без срока жизни.
- Метод отключения клиента существует, но не вызывается ни одним маршрутом и ни одной внутренней веткой.
- Незавершённые состояния авторизации очищаются интервалом раз в пять минут с таймаутом десять минут; для кэша клиентов такой очистки нет.
- Клиент создаётся с единственной опцией `connectionRetries`; остальные значения берутся из библиотеки.
- Проверено чтением `node_modules/telegram`: по умолчанию `floodSleepThreshold` равен 60 секундам, `connectionRetries` бесконечен, автопереподключение включено, цикл обновлений шлёт ping каждые 9 секунд на каждый подключённый клиент.
- Таймауты внешних вызовов построены на гонке промисов; таймеры после завершения гонки не снимаются.
- Лимит выборки вычисляется как минимум из 200 и произведения часов на 10; при большом окне результат обрезается молча.
- Ошибки Telegram отображаются только в 400 и 500; коды 401, 404 и 429 не используются.
- Невалидная сессия не вытесняется из кэша.
- Проверка сессии подавляет любую ошибку и возвращает единый признак неуспеха.
- В файле 38 вызовов `console.*`, включая вывод номера телефона, префикса строки сессии и её длины.

## Ограничения

- Кэш живёт в памяти одного процесса; перезапуск его обнуляет.
- Обход сообщений идёт последовательно и останавливается при выходе за временное окно.
- Значение `floodSleepThreshold` определяет, сколько времени запрос может занимать процесс при ограничении со стороны Telegram.

## Открытые вопросы

- Допустимый срок простоя клиента до вытеснения.
- Нужен ли внешний маршрут завершения сессии, помимо внутреннего вытеснения.
