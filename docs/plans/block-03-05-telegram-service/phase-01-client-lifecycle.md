# Phase 01 — Жизненный цикл клиентов и ресурсы

Статус: done

Требуемые правила: `.claude/rules/runtime-resources.md`, `.claude/rules/telegram.md`, `.claude/rules/patterns.md`, `.claude/rules/testing.md`

## Цель

Число живых клиентов ограничено, простаивающие освобождаются, при остановке процесса не остаётся открытых соединений.

## Заметки по реализации

Работа с кэшем выносится в отдельную область ответственности внутри сервиса и пишется с нуля: запись кэша хранит клиента и отметку последнего обращения. Файловое хранилище остаётся нетронутым соседом — его судьба решается в блоке 08-09.

## Объём

- Кэш клиентов ограничен константой SESSION_CACHE_MAX_ENTRIES; при достижении потолка вытесняется запись с самым давним обращением.
- Запись, к которой не обращались дольше SESSION_CACHE_IDLE_TTL_MS, вытесняется фоновым сбором с интервалом SESSION_CACHE_SWEEP_INTERVAL_MS.
- Вытеснение всегда отключает клиента; запись не удаляется из кэша без отключения.
- Остановка приложения отключает всех клиентов и снимает интервалы.
- Клиент создаётся с явными опциями из именованных констант: порог ожидания при флуд-вейте, ограниченное число попыток подключения и запросов.
- Таймеры, созданные для таймаутов внешних вызовов, снимаются после завершения вызова.
- Ошибка авторизации, означающая недействительную сессию, вытесняет запись из кэша.
- Долгоживущий интервал не удерживает цикл событий.

## Критерии приёмки

- Тест с поддельными таймерами подтверждает вытеснение простаивающей записи и вызов отключения.
- Поток уникальных сессий не поднимает размер кэша выше потолка.
- Ни один тест не открывает настоящее соединение MTProto.
- В коде не остаётся создания клиента без явных опций.

## Итог

- Кэш вынесен в `src/telegram/utils/session-client-cache.ts`: потолок SESSION_CACHE_MAX_ENTRIES с вытеснением давно не использованных, фоновый сбор простаивающих, каждое вытеснение вызывает `destroy`.
- Клиент освобождается через `destroy`, а не `disconnect`: только он останавливает цикл обновлений GramJS, который иначе переподключается.
- Константы в `src/telegram/constants.ts`; опции GramJS заданы явно в `createClient`.
- Таймауты внешних вызовов идут через `withTimeout`, таймер снимается в `finally`.
- Ошибки недействительной сессии (`isInvalidSessionError`) вытесняют запись в `checkSession` и `getChannelPosts`.
- `onModuleDestroy` снимает интервалы и освобождает кэшированных и ожидающих авторизации клиентов.
- Тесты `test-writer`: 4 новых набора, 53 теста; lint, build, `rtk npm test` (262 теста) проходят.
