# Phase 04 — Отправка в бота, расписание и ручной запуск

Статус: done

Требуемые правила: `.claude/rules/api-security.md`, `.claude/rules/api-contracts.md`, `.claude/rules/runtime-resources.md`, `.claude/rules/testing.md`

## Цель

Каждый день в 23:00 по Киеву и по запросу `POST /digest/run` готовый дайджест приходит в Telegram-бота.

## Заметки по реализации

- Разделы «Формат сообщения», «Маршруты» и «Отказы запуска» в [design.md](design.md).
- Зависимость `@nestjs/schedule` ставится через `rtk npm.cmd install` с мажорной версией, совместимой с Nest 10.
- Задача по расписанию регистрируется кодом через `SchedulerRegistry`, а не декоратором, потому что расписание и пояс приходят из окружения.
- Токен и id чата бота пользователь передаёт перед smoke-прогоном; до этого работа идёт на подделках.

## Объём

- `src/digest/utils/digest-formatter.ts` — HTML с экранированием, блоки тем и `viewpoints`, ссылки `@channel/id`, блок «Посты без текста», подвал «Учтено N из N» с недоступными и обрезанными каналами и флагами резерва; нарезка по BOT_MESSAGE_MAX_CHARS.
- `src/digest/bot-notifier.ts` — `sendMessage` по очереди, `disable_web_page_preview`, таймаут BOT_CALL_TIMEOUT_MS, ожидание `retry_after` не дольше BOT_MAX_RETRY_AFTER_S; URL и токен не логируются.
- `src/digest/digest.service.ts` — `start()` для маршрута: 409 при идущем запуске, 503 без конфигурации, иначе фоновый запуск; `run()` для расписания: пропуск с одной строкой лога при идущем запуске; флаг снимается в `finally`; итоговая строка лога с числами постов, тем, каналов и длительностью; резервный дайджест при отказе Grok.
- `src/digest/digest.scheduler.ts` — регистрация задачи с DIGEST_CRON и DIGEST_TIMEZONE при старте модуля, только если дайджест настроен; остановка задачи в `onModuleDestroy`.
- `src/digest/digest.controller.ts` — `POST /digest/run`, 202 с `DigestRunResponse`.
- `src/digest/interfaces/` — `DigestRunResult`, `DigestRunResponse`.

## Команды проверки

- `rtk npm.cmd run test:e2e`

## Критерии приёмки

- Ни одно сообщение, собранное форматтером, не длиннее BOT_MESSAGE_MAX_CHARS.
- Второй `POST /digest/run` во время работы первого получает 409; после завершения первого — 202.
- После остановки приложения в `SchedulerRegistry` не остаётся задач, открытых таймеров нет (тест с `--detectOpenHandles` не сообщает об утечках).

## Доказательства

- `rtk npm.cmd run lint`, `rtk npm.cmd run build` — без ошибок.
- `rtk npm.cmd test` — 50 наборов, 935 тестов, все зелёные.
- `rtk npm.cmd run test:e2e -- --detectOpenHandles` — 5 наборов, 67 тестов, открытых таймеров и соединений нет; задача по расписанию регистрируется при настроенном дайджесте и удаляется после `app.close`.
- Отчёт на 600 постов и 150 тем режется на сообщения не длиннее `BOT_MESSAGE_MAX_CHARS`, теги не разрываются, «Учтено 600 из 600».
- Второй `POST /digest/run` во время работы — 409, после завершения — снова 202 (тест `digest.service.spec.ts`).
- Часовой пояс проверен через `nextDate()`: 23:00 по Киеву — 20:00 UTC.
