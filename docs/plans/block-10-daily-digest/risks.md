# Блок 10 — Риски

## Режимы отказа

| Режим | Последствие | Признак |
|-------|-------------|---------|
| Строка сессии попала в лог, ключ Redis или ошибку | Полный доступ к аккаунту у любого, кто видит логи | Поиск по логам и коду находит значение |
| `SESSION_ENCRYPTION_KEY` утерян или сменён | Все сессии нечитаемы, нужна повторная авторизация | 401 после выката, строки лога об ошибке расшифровки |
| Redis недоступен | 503 на маршрутах с сессией не из кэша; дайджест после рестарта не стартует | Всплеск 503, итог запуска с ошибкой Redis |
| Модель пропустила посты | Нарушено главное требование — «ничего не потеряно» | Подвал «Учтено N из M» с N меньше M |
| Модель исказила или оценила содержание | Саммари вводит в заблуждение | Ручная выборочная сверка с постами |
| Запуск завис на Grok | Флаг «идёт работа» не снимается, следующие запуски отвечают 409 | 409 дольше суммарного таймаута |
| Ручные запуски подряд | Лишние расходы на Grok и лишняя нагрузка на аккаунт | Число запусков в логах за день |
| Перезапуск в 23:00 | Дайджест за день не приходит, догоняющего запуска нет | Нет сообщения в боте |
| Токен бота в логе или ошибке | Любой может писать от имени бота | Поиск по логам |
| Много каналов подряд | Flood wait Telegram на аккаунте | 429 в итоге запуска |

## Радиус поражения

- Phase 01 затрагивает путь каждой сессии: авторизацию, `/telegram/me`, посты. Ошибка ломает весь сервис, а не только дайджест.
- Phase 02-04 изолированы в `src/digest/` и двух новых методах фасада; ошибка ломает только дайджест.

## Цена недели с ошибкой в проде

- Утечка строки сессии — компрометация аккаунта; деньгами не измеряется.
- Цикл 409 из-за незакрытого флага — неделя без дайджеста, пока не перезапустят сервис.
- Ручные запуски без ограничения — до RATE_LIMIT_DEFAULT запросов в минуту, но одиночный запуск держит максимум один прогон одновременно; расход ограничен длительностью прогона.
- Redis на Railway — постоянная плата за плагин.

## Экспозиция секретов

- Новые секреты: `SESSION_ENCRYPTION_KEY`, `GROK_API_KEY`, `TELEGRAM_BOT_TOKEN`, `REDIS_URL` (содержит пароль). Все читаются только загрузчиками `src/config/`, не логируются, не попадают в текст ошибок.
- Токен бота входит в URL исходящего запроса к Bot API: URL не логируется и не включается в сообщение исключения.
- Тексты постов приватных каналов уходят в Grok. Это осознанная передача третьей стороне, следствие требования пользователя.
- Тесты используют очевидные подделки для ключей, токенов и строк сессий.

## Меры

- Флаг одиночного запуска снимается в `finally`; суммарная длительность ограничена таймаутами всех внешних вызовов.
- Каналы обрабатываются строго по одному.
- Проверка полноты — кодом, а не доверием модели; резервные блоки гарантируют N из N.
- Отдельный тест на отсутствие строки сессии, ключа и токена в логах на путях Phase 01-04.

## Ход отката

- Phase 01: убрать `REDIS_URL` из окружения — сервис уходит в режим «только память» без выката кода. Полный откат — выкат 1.4.1; записи в Redis остаются нечитаемыми без ключа и удаляются очисткой плагина.
- Phase 02-04: убрать `DIGEST_CHANNELS` — задача по расписанию не регистрируется, `POST /digest/run` отвечает 503. Полный откат — выкат 1.4.1.
- Утечка ключа шифрования: сменить `SESSION_ENCRYPTION_KEY`, очистить Redis, завершить сессии в настройках Telegram, авторизоваться заново.
