## Затронутые файлы

- `src/telegram/session-store.ts` — единственный владелец клиентов; сейчас неизвестная строка сессии даёт 401, кэш только в памяти.
- `src/telegram/auth.service.ts` — `completeLogin` передаёт клиента в `SessionStore.adopt`.
- `src/telegram/telegram.service.ts` — фасад, экспортируется из `TelegramModule`; порядок остановки.
- `src/telegram/channel.service.ts` — обход канала страницами, окно по часам, потолок `POSTS_MAX_MESSAGES`, флаг `isTruncated`.
- `src/telegram/telegram-client.factory.ts` — `create(sessionString)` уже умеет строить клиента из сохранённой строки.
- `src/telegram/telegram.module.ts` — регистрирует глобальные guard-ы (`APP_GUARD`), экспортирует `TelegramService`.
- `src/telegram/interfaces/message.interface.ts` — `TelegramPost` (`id`, `text`, `date`, `media`, `postUrl`).
- `src/app.module.ts` — корневой модуль, `ConfigModule` глобальный.
- `src/config/` — загрузчики окружения; новые переменные читаются только через них.
- `src/shared/guards/` — `ApiKeyGuard`, `RateLimitGuard` применяются ко всем маршрутам глобально.
- `docs/plans/block-08-09-refactor-strictness-storage/adr-session-storage.md` — действующее решение «только память», которое этот блок заменяет.
- `.claude/rules/telegram.md`, `.claude/rules/architecture.md`, `.claude/rules/runtime-resources.md`, `CLAUDE.md` — фиксируют модель «только память» и запрет на слой хранения без решения пользователя.

## Ограничения из правил

- Пакет `telegram` (GramJS) импортируется только внутри `src/telegram/`. Bot API вызывается по HTTP и к GramJS не относится.
- Строка сессии не логируется, не попадает в URL, в ошибку, в файл репозитория и не покидает модуль `telegram`, кроме ответа авторизации.
- Каждый внешний вызов ограничен таймаутом, таймер очищается.
- Каждый ресурс имеет потолок и путь освобождения; интервалы и задачи по расписанию очищаются при остановке.
- Все маршруты, кроме health, требуют `x-api-key` и лимит частоты.
- Логи: один итог на операцию, без поштучных строк.
- Параллельные запросы к Telegram от одного аккаунта без ограничения запрещены.
- Новая переменная окружения документируется в `CLAUDE.md` и читается загрузчиком в `src/config/`.
- Запуск сервиса не падает без конфигурации: health остаётся живым.
- Тесты: реальный `TelegramClient`, реальный Redis, реальный Grok и реальный Bot API в тестах запрещены.

## Внешние системы

- Redis — хранилище ключ-значение; на Railway подключается плагином, адрес приходит в `REDIS_URL`.
- Grok (xAI) — HTTP API, совместимый с форматом chat completions; поддерживает ответ по JSON-схеме. Точные имена моделей и параметры структурированного ответа сверить через context7 на старте Phase 03.
- Telegram Bot API — `sendMessage`, предел длины одного сообщения 4096 символов, `parse_mode` HTML, ответ 429 содержит `retry_after`.
- Node 20 — встроенный `fetch` и `AbortSignal.timeout`, отдельная HTTP-библиотека не нужна.
- Планировщик — `@nestjs/schedule` (совместимая с Nest 10 мажорная версия сверяется при установке), часовой пояс задаётся задаче.
- Клиент Redis — `ioredis`, поддерживает таймаут команды, ограничение повторов подключения, `quit`.
