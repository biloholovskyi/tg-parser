# ADR — Сессии в Redis

Дата: 24.09.2026

Статус: принято пользователем. Заменяет [adr-session-storage.md](../block-08-09-refactor-strictness-storage/adr-session-storage.md).

## Контекст

Ежедневный дайджест запускается по расписанию без участия человека и читает каналы от имени аккаунта Telegram. При модели «только память» любой перезапуск или выкат стирает все сессии, и дайджест молча перестаёт работать до ручной повторной авторизации.

## Варианты

- Все сессии в Redis, зашифрованные — любая выданная сессия переживает перезапуск; дайджест использует одну из них.
- Только сессия дайджеста в Redis — меньше данных вне процесса, но две модели хранения в одном сервисе.
- Строка сессии в переменной окружения — без новой зависимости, но секрет задаётся руками и меняется только через редеплой.

## Решение

Все сессии хранятся в Redis в зашифрованном виде.

- Ключ записи — SHA-256 от строки сессии; сама строка в ключе не встречается.
- Значение — строка сессии, зашифрованная AES-256-GCM (симметричный шифр с проверкой целостности) ключом из `SESSION_ENCRYPTION_KEY`.
- Запись живёт `SESSION_STORE_TTL_S` и продлевается при каждом использовании; неиспользуемая сессия исчезает сама.
- Сессия, отвергнутая Telegram, удаляется из Redis и из памяти сразу.
- Живые клиенты GramJS по-прежнему живут только в ограниченном кэше памяти; Redis хранит строки, а не соединения.
- Незавершённые попытки входа остаются в памяти, как раньше.
- Отметка «эта сессия используется дайджестом» — отдельный ключ в Redis со ссылкой на хеш сессии.
- Без `REDIS_URL` или без ключа шифрования сервис работает в режиме «только память» и пишет одно предупреждение при старте.

## Последствия

- Перезапуск не требует повторной авторизации ни от вызывающих, ни от дайджеста.
- Появляется внешняя зависимость: недоступный Redis даёт 503 на маршрутах, которым нужна сессия не из кэша.
- Утечка базы Redis без ключа шифрования не раскрывает сессий; утечка ключа вместе с базой раскрывает все.
- Потеря или смена ключа делает все записи нечитаемыми: они удаляются при чтении, нужна повторная авторизация.
- Горизонтальное масштабирование по-прежнему не включено: кэш клиентов остаётся в процессе, отдельное решение.
