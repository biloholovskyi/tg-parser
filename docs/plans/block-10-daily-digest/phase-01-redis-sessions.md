# Phase 01 — Сессии в Redis

Статус: done (прохождение инструкции на Railway за пользователем)

Требуемые правила: `.claude/rules/telegram.md`, `.claude/rules/runtime-resources.md`, `.claude/rules/architecture.md`, `.claude/rules/testing.md`

## Цель

Любая выданная сессия переживает перезапуск процесса и хранится в Redis только в зашифрованном виде.

## Заметки по реализации

- Решение: [adr-session-redis.md](adr-session-redis.md); ключи и поведение: раздел «Хранение сессий» в [design.md](design.md); риски: [risks.md](risks.md).
- Самая рискованная фаза блока, поэтому первая: она трогает путь каждой сессии.
- `SessionRepository` пишется с нуля; `SessionStore` дополняется, его публичные методы сохраняют сигнатуры.
- Зависимость `ioredis` ставится через `rtk npm.cmd install`.

## Объём

- `src/config/redis.config.ts` — загрузчик `REDIS_URL` и `SESSION_ENCRYPTION_KEY`; неверная длина ключа — предупреждение и режим «только память».
- `src/redis/redis.module.ts` — провайдер клиента, который подключается при старте (строка `Connected` в логе подтверждает настройку), с `commandTimeout` = REDIS_COMMAND_TIMEOUT_MS, ограниченными повторами REDIS_MAX_RETRIES; `quit` в `onApplicationShutdown`, то есть после освобождения клиентов Telegram; без конфигурации провайдер равен `null`.
- `src/shared/utils/secret-cipher.ts` — `encryptSecret`, `decryptSecret`, `hashSecret`; случайный iv на каждую запись.
- `src/telegram/session-repository.ts` — `save`, `isKnown`, `touch`, `remove`, `markDigest`, `loadDigest`; ошибки расшифровки удаляют запись и дают «нет сессии».
- `src/telegram/session-store.ts` — промах кэша поднимает клиента из репозитория; `adopt` сохраняет; `evictIfSessionInvalid` удаляет и из репозитория; простой сброс по бездействию Redis не трогает.
- `src/telegram/constants.ts` — SESSION_STORE_TTL_S и ключевые префиксы.
- `src/telegram/telegram.module.ts` — импорт `RedisModule`, провайдер `SessionRepository`.
- Порядок остановки: клиенты освобождаются до закрытия Redis.
- Ошибка Redis на пути запроса отображается в 503 через `src/telegram/utils/telegram-errors.ts`.
- `docs/deployment/railway-redis.md` — подробная пошаговая инструкция на русском, ссылка на неё из `DEPLOYMENT.md`. Разделы:
  - добавление Redis в проект Railway (Dashboard и CLI);
  - подстановка `REDIS_URL` в сервис `tg-parser` через ссылку на переменную Redis-сервиса и приватную сеть Railway, без публичного адреса;
  - включение сохранения данных на диск Redis (том, режим записи), чтобы сессии переживали перезапуск самого Redis;
  - генерация `SESSION_ENCRYPTION_KEY` одной командой (PowerShell и bash), где его хранить и почему его нельзя терять;
  - установка переменных и редеплой;
  - проверка: строка лога при старте без предупреждения о режиме «только память», авторизация, рестарт сервиса, `/telegram/me` — `success`;
  - локальный запуск Redis для разработки;
  - смена ключа и полная очистка сессий при утечке;
  - типовые ошибки: нет подключения, неверный ключ, 503 на маршрутах;
  - стоимость плагина и как её посмотреть.
- В инструкции только заглушки вместо значений: ни реального адреса, ни пароля, ни ключа.

## Критерии приёмки

- Сессия, выданная до перезапуска процесса, после перезапуска проходит `/telegram/me` со статусом `success` (проверка в тесте с подделкой Redis, общей для двух экземпляров `SessionStore`).
- Ни один ключ Redis и ни одно значение в открытом виде не содержат строку сессии.
- Без `REDIS_URL` все существующие тесты проходят без изменения ожиданий.
- Поиск по `src/` не находит `new Redis(` вне `src/redis/`.
- По инструкции без дополнительных вопросов Redis поднят на Railway, и сессия переживает редеплой сервиса.

## Доказательства

- `rtk npm.cmd run lint`, `rtk npm.cmd run build` — без ошибок.
- `rtk npm.cmd test` — 32 набора, 641 тест, все зелёные.
- `rtk npm.cmd run test:e2e` — 4 набора, 50 тестов, все зелёные; `REDIS_CLIENT` в E2E равен `null`.
- Перезапуск проверен тестами `session-store.spec.ts` и `telegram.service.spec.ts`: два экземпляра с общей подделкой Redis, `checkSession` — `success`.
- Гигиена секретов: тесты проверяют логи всех уровней и все ключи и значения Redis на отсутствие строки сессии и ключа.
- `new Redis(` встречается только в `src/redis/redis-client.ts`.
