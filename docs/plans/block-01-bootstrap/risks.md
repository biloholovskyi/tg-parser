# Блок 01 — Риски

## Режимы отказа

| Режим | Последствие | Признак |
|-------|-------------|---------|
| `ValidationPipe` с `forbidNonWhitelisted` отклоняет поля, которые шлёт действующий клиент | Интеграции ломаются на 400 | Всплеск 400 на `/telegram/auth` сразу после выката |
| Список источников CORS задан неверно | Браузерный клиент теряет доступ | Ошибки CORS в браузере, серверные вызовы работают |
| Фоновое отклонение промиса логируется и не завершает процесс | Скрытая деградация вместо явного падения | Рост числа записей уровня error без перезапусков |
| Health-маршрут объявлен по одному пути, а внешний мониторинг опрашивает другой | Внешний мониторинг считает сервис мёртвым | Алерты мониторинга без реальных ошибок |

## Радиус поражения

Вся HTTP-поверхность разом: и валидация, и CORS применяются глобально. Ошибка конфигурации затрагивает все эндпоинты одновременно, а не один маршрут.

## Цена недели с ошибкой в проде

- Слишком строгая валидация: полный отказ приёма запросов, простой интеграций.
- Оставшийся `process.exit`: цикл перезапусков, потеря кэша сессий, повторная авторизация всех клиентов и лишний трафик к Telegram.

## Экспозиция секретов

Прямой нет: план не трогает учётные данные. Косвенная — логирование фоновых ошибок вместо завершения процесса может вывести содержимое ошибки GramJS. Сообщения ошибок логируются без полезной нагрузки запроса.

## Ход отката

Откат на предыдущий релиз Railway. Изменения затрагивают только загрузку приложения и не оставляют состояния на диске и в Telegram, поэтому откат полный и немедленный. Промежуточный вариант — список источников CORS переводится в разрешающий через переменную окружения без выката кода.
