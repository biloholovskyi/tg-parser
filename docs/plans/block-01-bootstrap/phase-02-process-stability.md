# Phase 02 — Устойчивость процесса и health-проверка

Статус: done

Требуемые правила: `.claude/rules/runtime-resources.md`, `.claude/rules/patterns.md`, `.claude/rules/testing.md`

## Цель

Фоновая ошибка сети не завершает процесс, а health-проверка остаётся единственной и дешёвой.

## Заметки по реализации

Обработчики верхнего уровня переписываются с нуля. Встроенный `AppController` в `src/app.module.ts` сокращается до одного маршрута либо выносится, если маршрут остаётся.

## Объём

- Необработанное отклонение промиса логируется через `Logger` с контекстом и не завершает процесс.
- Необработанное исключение логируется и завершает процесс осознанно, через штатную остановку приложения, а не мгновенным `process.exit`.
- Остановка по сигналу закрывает приложение и даёт отработать хукам остановки.
- Health-проверка объявлена в одном месте, соответствует пути из `railway.toml`, отдаёт константный ответ и не обращается ни к Telegram, ни к конфигурации учётных данных.
- Порт по умолчанию согласован с `internal_port` из `railway.toml`.

## Критерии приёмки

- E2E-тест: health-маршрут отвечает 200 при отсутствующих переменных Telegram.
- Тест: эмуляция отклонённого промиса не приводит к завершению процесса и оставляет запись в логе.
- В `src/main.ts` не остаётся `process.exit` в обработчике общего вида.

## Доказательства

- `src/shared/utils/process-handlers.ts` — `unhandledRejection` только логируется через `Logger` и процесс продолжает обслуживать запросы; `uncaughtException` логируется и уходит в `closeApplication`, которая закрывает приложение (хуки остановки отрабатывают) и лишь затем завершает процесс; `SIGTERM` и `SIGINT` идут тем же путём с кодом успеха; `describeError` не выводит полезную нагрузку.
- `src/main.ts` — переписан: `Logger` вместо `console.*`, порт по умолчанию `DEFAULT_PORT`, обработчики подключаются после создания приложения. Оставшийся `process.exit` только в ветке неудачного старта, где приложения ещё нет; в обработчиках общего вида его нет.
- `src/app.module.ts` — встроенный `AppController` удалён вместе с дублирующими `/` и `/health`.
- `src/telegram/telegram.controller.ts` — health отдаёт константный `{ status: 'ok' }` без `timestamp`. Отклонение от раздела Границы индекса: правка на одну строку в этом файле была неизбежна, иначе единственный health-маршрут не мог отдавать константный ответ.
- `src/shared/constants/http.constants.ts` — `DEFAULT_PORT` совпадает с `internal_port` из `railway.toml`; `CLAUDE.md` обновлён (порт по умолчанию 8080).
- Тесты (`test-writer`): `process-handlers.spec.ts` (16), `http.constants.spec.ts` (2, drift-гард на `internal_port`), `test/app.e2e-spec.ts` (5, health при отсутствующих переменных Telegram, drift-гард на `healthcheck_path`, 404 на `/` и `/health`, `TelegramService` замокан).
- Гейты: `rtk npm run lint` чисто, `rtk npm run build` чисто, `rtk npm test` — 7 suites, 59 тестов, `rtk npm run test:e2e` — 1 suite, 5 тестов. Все зелёные.
