# Блок 01 — Research

Факты по затронутой поверхности. Без решений.

## Затрагиваемые файлы

- `src/main.ts` — bootstrap, CORS, порт, обработчики сигналов и фоновых ошибок
- `src/app.module.ts` — корневой модуль, `ConfigModule`, встроенный `AppController`
- `src/config/` — место для загрузчика новых переменных окружения

## Наблюдаемое состояние

- Глобальный `ValidationPipe` не зарегистрирован, поэтому декораторы `class-validator` в DTO не исполняются.
- `app.enableCors()` вызывается без аргументов: разрешены любые источники.
- Обработчики `uncaughtException` и `unhandledRejection` завершают процесс через `process.exit(1)`.
- `app.enableShutdownHooks()` подключён, обработчики `SIGTERM` и `SIGINT` закрывают приложение.
- Маршруты `/` и `/health` объявлены в `AppController` внутри `src/app.module.ts`; `railway.toml` использует `/telegram/health`.
- Порт берётся из `process.env.PORT` со значением по умолчанию 3000; `railway.toml` объявляет `internal_port = 8080`.

## Ограничения

- Health-проверка платформы не должна зависеть от Telegram и от конфигурации учётных данных.
- Загрузка приложения не падает при отсутствующих `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` — это зафиксированное требование `.claude/rules/telegram.md`.
- Список разрешённых источников CORS зависит от среды, значит читается из переменной окружения через загрузчик в `src/config/`.
- GramJS порождает фоновые отклонения промисов при обычных сетевых сбоях.

## Открытые вопросы

- Имя переменной окружения со списком источников CORS.
- Нужен ли отдельный ответ health для платформы и для оператора, или достаточно одного.
