# Redis на Railway: хранение сессий

Инструкция подключает Redis к сервису `tg-parser`, чтобы сессии Telegram переживали перезапуск и деплой. Без Redis сервис работает как раньше: сессии живут только в памяти и пропадают при каждом перезапуске.

Что где хранится:

- В Redis лежат строки сессий, зашифрованные ключом `SESSION_ENCRYPTION_KEY`. Ключ записи — хеш SHA-256 от строки сессии, сама строка в открытом виде нигде не встречается.
- Ещё один ключ, `tg:digest-session`, хранит хеш сессии, от имени которой дайджест читает каналы.
- Каждая запись живёт 30 дней с последнего использования (константа `SESSION_STORE_TTL_S`), потом удаляется сама.
- Ключ шифрования хранится только в переменных Railway. Без него записи в Redis бесполезны: и для злоумышленника, и для самого сервиса.

Нужно две переменные окружения в сервисе `tg-parser`:

- `REDIS_URL` — адрес Redis, берётся ссылкой на переменную Redis-сервиса;
- `SESSION_ENCRYPTION_KEY` — 32 случайных байта в base64 (строка из 44 символов, оканчивается на `=`).

Если хотя бы одна из них не задана или ключ неверной длины, сервис стартует в режиме «только память» и пишет одно предупреждение в лог.

## Шаг 1. Добавить Redis в проект

Через Dashboard:

1. Открой проект, в котором уже развёрнут `tg-parser`.
2. Нажми "+ Create" (или "New") на холсте проекта, выбери "Database", затем "Redis".
3. Дождись, пока у нового сервиса Redis появится зелёный статус.
4. Открой сервис Redis, вкладка "Variables". Там должна быть переменная `REDIS_URL`: это внутренний адрес вида `redis://default:<пароль>@redis.railway.internal:6379`.

Через CLI (из папки проекта, связанной командой `railway link`):

```bash
railway add --database redis
```

Redis должен быть в том же проекте и в том же окружении (environment), что и `tg-parser`. Иначе внутренний адрес `redis.railway.internal` не будет виден.

Запомни имя сервиса Redis на холсте (по умолчанию `Redis`): оно нужно в ссылке на переменную в шаге 3.

## Шаг 2. Проверить, что Redis сохраняет данные на диск

Сессии должны пережить не только перезапуск `tg-parser`, но и перезапуск самого Redis. Для этого данные Redis должны лежать на томе (volume) — постоянном диске Railway, который не стирается при деплое.

1. Открой сервис Redis на холсте. Под ним должен быть подключённый том (значок диска, вкладка "Volumes" или раздел "Volume" в настройках).
2. Если тома нет: в настройках сервиса Redis добавь Volume с путём монтирования `/data`.
3. Чтобы Redis записывал каждое изменение, а не только периодические снимки, включи журнал: в настройках сервиса Redis, в поле "Custom Start Command", задай

```bash
redis-server --appendonly yes --dir /data --requirepass $REDIS_PASSWORD
```

Если в шаблоне уже есть своя команда запуска, не заменяй её целиком: добавь к ней `--appendonly yes`. После изменения Railway перезапустит Redis.

Проверка: во вкладке "Data" сервиса Redis (или через `redis-cli` в шаге 7) должна открываться база. После перезапуска Redis ключи `tg:session:*` не должны пропадать.

## Шаг 3. Передать адрес Redis в `tg-parser`

1. Открой сервис `tg-parser`, вкладка "Variables".
2. Нажми "New Variable".
3. Имя — `REDIS_URL`, значение — ссылка на переменную Redis-сервиса:

```text
${{Redis.REDIS_URL}}
```

Вместо `Redis` подставь имя сервиса Redis на холсте, если оно другое. Railway сам подставит актуальный адрес и пароль. Если пароль Redis поменяется, ссылка обновится сама.

Не копируй адрес руками. Не используй `REDIS_PUBLIC_URL`: он ведёт в Redis из интернета через прокси, стоит дороже по трафику, и через него можно подобрать пароль.

Закрой Redis от интернета: сервис Redis, вкладка "Settings", раздел "Networking" → "Public Networking". Если там есть TCP Proxy (адрес вида `*.proxy.rlwy.net:<порт>`), удали его. `tg-parser` ходит в Redis только по внутренней сети, публичный адрес ему не нужен. Открытый Redis позволяет стереть все сессии или подменить сессию дайджеста.

Через CLI:

```bash
railway variables --service tg-parser --set 'REDIS_URL=${{Redis.REDIS_URL}}'
```

Одинарные кавычки нужны, чтобы оболочка не пыталась подставить `${{...}}` сама.

## Шаг 4. Сгенерировать ключ шифрования

Ключ — 32 случайных байта в base64. Сгенерируй его один раз любой из команд:

Node.js (работает везде, где установлен Node):

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

PowerShell 7:

```powershell
[Convert]::ToBase64String([System.Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
```

bash с OpenSSL:

```bash
openssl rand -base64 32
```

Правила обращения с ключом:

- Не коммить его, не присылай в чаты и задачи, не клади в `.env`, который попадает в репозиторий.
- Сохрани копию в менеджере паролей. Если ключ пропадёт из Railway, все сохранённые сессии станут нечитаемыми, и нужно будет авторизоваться заново.
- Один ключ на окружение. Для локальной разработки сгенерируй отдельный.

## Шаг 5. Добавить ключ в `tg-parser`

1. Сервис `tg-parser`, вкладка "Variables", "New Variable".
2. Имя — `SESSION_ENCRYPTION_KEY`, значение — строка из шага 4.

Через CLI:

```bash
railway variables --service tg-parser --set "SESSION_ENCRYPTION_KEY=<строка из шага 4>"
```

## Шаг 6. Задеплоить

После изменения переменных Railway предложит применить изменения ("Deploy" или "Apply changes"). Подтверди. Если не предложил — "Deployments", затем "Redeploy" на последнем деплое.

## Шаг 7. Проверить

1. Логи деплоя (`railway logs --service tg-parser` или "Deployments" → "View Logs"). При старте должны быть строки:
   - `[RedisModule] Session persistence: Redis`
   - `[Redis] Connected`

   И не должно быть строки `sessions are kept in memory only`.
2. Авторизуйся через `POST /telegram/auth`, как в [DEPLOYMENT.md](../../DEPLOYMENT.md), шаг 5. Получи `sessionString`.
3. Проверь сессию:

```bash
curl https://твой-домен.up.railway.app/telegram/me \
  -H "x-api-key: твой_ключ" \
  -H "x-session-string: строка_сессии"
```

   Ответ: `{"status":"success"}`.
4. Перезапусти сервис: "Deployments" → последний деплой → "Restart" (или `railway redeploy --service tg-parser`).
5. Повтори запрос из пункта 3 с той же строкой сессии. Ответ снова `{"status":"success"}`, без повторной авторизации.
6. Необязательно: убедись, что в Redis лежит хеш, а не строка сессии. Во вкладке "Data" сервиса Redis видны ключи вида `tg:session:3f2a…` (64 шестнадцатеричных символа), значения — нечитаемый base64.

## Локальная разработка

Запусти Redis в Docker:

```bash
docker run -d --name tg-redis -p 6379:6379 redis:7-alpine
```

В локальном `.env` (он не коммитится) добавь:

```text
REDIS_URL=redis://localhost:6379
SESSION_ENCRYPTION_KEY=<отдельный локальный ключ из шага 4>
```

Без этих строк локальный сервис работает в режиме «только память»: это нормально для разработки.

Тесты не используют Redis: и unit-, и E2E-тесты запускаются без него.

## Смена ключа и полная очистка сессий

Когда нужно: ключ мог утечь, утекла база Redis, или нужно разом завершить все сессии.

1. Сгенерируй новый ключ (шаг 4) и замени `SESSION_ENCRYPTION_KEY` в `tg-parser`.
2. Задеплой. Старые записи не расшифруются новым ключом: сервис удаляет каждую при первом обращении и отвечает 401.
3. Очисти Redis, чтобы не ждать удаления по обращению: вкладка "Data" сервиса Redis. Если нужен `redis-cli`, запусти его внутри сервиса Redis (`railway ssh --service Redis`, затем `redis-cli -a $REDIS_PASSWORD FLUSHDB`), не открывая публичный доступ.
4. Если ключ или база утекли: в Telegram на телефоне открой "Настройки" → "Устройства" и заверши сессии, созданные сервисом. Без этого утёкшая строка сессии остаётся рабочей в самом Telegram, независимо от Redis.
5. Авторизуйся заново и, когда появится дайджест, снова отметь его сессию.

## Типовые ошибки

- В логе `sessions are kept in memory only` — не задан `REDIS_URL` у `tg-parser`, или ключ не 32 байта. Проверь `railway variables --service tg-parser`. Строка из шага 4 должна быть длиной 44 символа.
- В логе `[Redis] Connection error (ENOTFOUND)` — Redis в другом проекте или окружении, либо в ссылке указано неверное имя сервиса.
- `[Redis] Connection error (ECONNREFUSED)` или `(ETIMEDOUT)` — Redis остановлен или перезапускается. Сервис переподключается сам, раз в 30 секунд или чаще. Когда связь вернётся, в логе появится `Connection restored`.
- `WRONGPASS` или `NOAUTH` — адрес скопирован руками и устарел. Замени значение на ссылку `${{Redis.REDIS_URL}}`.
- Ответ 503 `Session storage is unreachable, retry later` — Redis не ответил. Сессии, уже поднятые в памяти, продолжают работать. Сессии после перезапуска не поднимутся, пока Redis недоступен.
- 401 для сессии, которая работала до деплоя, — сменился `SESSION_ENCRYPTION_KEY`, запись истекла (30 дней без использования) или Telegram отозвал сессию. Авторизуйся заново.

## Стоимость

Redis на Railway оплачивается по использованию: память, процессор и объём тома. Для хранения сессий нагрузка минимальная: несколько записей по сотне байт и одна команда на запрос. Текущий расход виден в "Usage" в настройках аккаунта или проекта, по каждому сервису отдельно. Чтобы ограничить расход, в настройках сервиса Redis задай лимит ресурсов ("Resource Limits").

## Откат

Удали переменную `REDIS_URL` у `tg-parser` и задеплой. Сервис вернётся в режим «только память». Записи в Redis останутся, но использоваться не будут. Сам сервис Redis после этого можно удалить.
